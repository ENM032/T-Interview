## Overview

Choosing between **Agile** and **Waterfall** methodologies dictates how teams plan budgets, manage milestones, communicate with stakeholders, and deliver value.

```
[ Waterfall (Linear) ]
Requirements ──> Design ──> Implementation ──> Verification ──> Deployment

[ Agile (Iterative Cycles) ]
   ┌──────────────────────────────┐
   │ Plan ──> Build ──> Test ──>  │  ──> [ Working Increment Shipped ]
   │  ^                       │   │
   │  └───── Review & Retro ──┘   │
   └──────────────────────────────┘ (Repeats every 2 weeks)
```

---

## Detailed Comparison

| Attribute | Waterfall Methodology | Agile Methodology |
|---|---|---|
| **Approach** | Sequential, Linear | Iterative, Incremental |
| **Requirements** | Defined upfront, strict change control | Continuously refined via user stories |
| **Delivery** | Single major release at the end | Regular working increments (e.g., bi-weekly) |
| **Risk Management** | High risk late in the cycle | Early and continuous risk mitigation |
| **Customer Involvement** | Mainly during initiation & acceptance | Constant collaboration throughout sprints |
| **Best For** | Fixed scope, high-regulation, physical builds | Digital software, fast-moving tech markets |
