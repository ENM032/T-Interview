## Overview

The **Triple Constraint** (or *Project Management Triangle*) is one of the most foundational principles of project delivery. Every project operates within finite boundaries.

```
                  [ SCOPE ]
                 /         \
                /   QUALITY \
               /             \
        [ TIME ] ─────────── [ COST ]
```

---

## Managing The Triple Constraint

* If **Scope** increases $\rightarrow$ **Time** (schedule) must be extended OR **Cost** (budget/headcount) must increase; otherwise **Quality** deteriorates.
* If **Deadline (Time)** is cut $\rightarrow$ **Scope** must be reduced OR **Cost** increased (adding contractors/overtime).
* In traditional **Waterfall**: Scope is fixed; Time and Cost are estimated.
* In **Agile**: Time and Cost (Sprint capacity) are fixed; Scope is flexible based on priority.

---

## What is Scope Creep & How to Prevent It

### Primary Causes:
1. Informal stakeholder chats ("Can you just add this small button?").
2. Poorly written requirements and ambiguous user stories.
3. Fear of saying "No" to important executive sponsors.

### Prevention Strategies:
* **Establish a Formal Change Control Process**: Require all new features to be sized and prioritized against existing deliverables.
* **Traceable Requirements (WBS / User Stories)**: Clearly articulate what is **In Scope** and what is explicitly **Out of Scope** in the project charter.
* **Constructive Trade-off Conversations**: Instead of refusing requests, explain the impact: *"We can certainly add this export feature, but it will push the delivery date back by one sprint unless we postpone the notifications feature."*
